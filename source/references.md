# 参考与取舍

这套系统没有从零发明通用的东西。成熟的设计系统已经把布局、状态、无障碍这些问题解决过了，这里把它们借来；自己的理念只落在它们没管的那一层：颜色的出处、标题的字、印章、纹样、留白和说话的方式。

下面写明向谁借了什么、没借什么。给这套系统加新东西时，照同样的方法做：先看成熟系统怎么解决，取它的结构，再用这里的令牌和原则重画。

| 参考 | 借来的 | 没借的 |
| --- | --- | --- |
| Apple 人机界面指南 | 44px 触控尺寸、大标题、分组列表、毛玻璃材质、底部标签栏与弹层、用原生选择器 | 系统蓝、SF 之外不考虑其他平台的做法 |
| Material Design 3 | 按窗口宽度分三级的自适应布局、同一内容在不同宽度换形态、令牌分「原始值」与「语义」两层的思路、每个控件列全状态 | 水波纹、动态取色、悬浮按钮、大面积色块 |
| IBM Carbon | 栅格纪律、动效分快慢两档且只为功能服务、表格与数据展示的规矩 | 直角、高密度、工业感 |
| Ant Design | 中文界面的排版习惯、表单与表格在业务场景里的组合方式 | 企业后台的密度、默认蓝 |
| GOV.UK 设计系统 | 文案的写法：说人话、报错讲清怎么办、一页一件事；表单的结构 | 视觉风格 |
| WAI-ARIA 创作实践 | 弹窗、标签页、开关、进度等控件的键盘操作与读屏语义 | 无 |
| WCAG 2.2 | 文字对比度 4.5:1、控件与图标 3:1、不单靠颜色传达信息、尊重「减弱动态效果」 | 无 |
| 中文排版需求（W3C） | 中西文间距、标点、竖排的规则 | 无 |
| 中国传统工艺 | 石青的蓝（宋人青绿山水里的矿物颜料）、朱砂印泥的红、宣纸的白；篆刻的白文与朱文、边栏；刺绣的平针与挑花；青铜器与织锦的回纹；袍服的海水纹；线装书的题签 | 水墨笔触、祥云贴图、龙凤、仿旧纹理、大红大金 |

## 在结构上参考的系统

上面那张表管的是界面本身。下面这些系统看的是另一件事：一套设计系统怎么分门别类、设计稿和代码怎么对齐。2026 年 11 月 19 日打开各自的官网核对过，只写了当时在页面上看到的做法。

| 参考 | 它的做法 | 这里取什么 |
| --- | --- | --- |
| GitHub Primer | 顶层分成 Product UI 和 Brand UI 两套，各有自己的基础和组件；品牌素材另有一个站。Figma 里把基础变量和组件分成不同的库，并要求组件「小而简单，用属性，不用层层嵌套」 | 按产物分类：办事的界面和品牌、平面物料分开讲，共用一套基础 |
| IBM Design Language 与 Carbon | 设计语言（理念、字体、颜色、摄影、插画、栅格）是一个站，Carbon（基础、组件、模式、数据可视化）是另一个站，后者声明自己由前者塑造。Figma 的基础库按颜色、图标、象形图、字体分开 | 审美标准和出处单独成一节，组件规范引用它，不混在一起写 |
| Atlassian | 文档分「开始、基础、组件、工具」；标志和插画放在基础里，品牌素材在站外。令牌被称作设计决定的唯一出处，并有可搜索的令牌表 | 令牌页做成能查的表；标志、印、图标归到基础 |
| Microsoft Fluent 2 | 文档分「设计、开发、组件」。Figma 套件分层：一份设计语言文件放全局变量和别名变量（含明暗、品牌几种模式），上面才是组件库；组件嵌套不超过两层 | 如果做 Figma 版本，照这个分层：变量一份，组件一份，图标一份 |
| Adobe Spectrum | 基础里有一条「注意力层级」：一页里只有一个元素或一组元素可以最抢眼 | 和「朱砂一处」是同一个道理，可以互相印证 |
| 抖音 Semi Design | 文档里有「设计协作」一组（定制主题、设计稿转代码、暗色模式、设计资源）和文案规范。色板上每个颜色都标了对比度等级 | 色彩令牌页给每个文字色标出对比度 |
| 字节 Arco Design | 设计一侧分「设计价值观、设计原则、样式指南、组件用法」；Figma 资源按 Web、移动、中后台模板、图标分成四份 | 设计指南和开发指南分开入口 |
| 日本数字厅设计系统 | 分「开始、指南、基本设计、组件、资源」。字体样式的名字直接带字号、字重和行高；整站文档可以打包成 Markdown 下载；日文正文行高不低于 1.5，不用斜体 | 文档提供一份可下载的纯文本；汉字不设斜体这一条这里已经有了 |

没能核对的：Shopify Polaris 的旧站已经跳转到开发者文档；腾讯 TDesign 只读到了价值观一页。这两个没有写进表里。

## 融合的方法

- **结构从众，气质从己。** 一个控件长什么样、怎么操作，跟着使用者已有的习惯走；它用什么颜色、配什么字、周围留多少白，由这套系统决定。
- **借规则，不借皮肤。** 从别的系统里拿的是「为什么」和「怎么分」，不是它的色值和圆角。
- **传统元素要有出处，也要能说清为什么是它。** 每加一种纹样或形制，写明它原本用在哪里、在界面里对应什么位置。说不清的不加。
- **减法优先。** 借来的东西如果和「先留白，再落笔」冲突，删掉它。

## 适合与不适合

适合：阅读、写作、笔记、日程、生活方式、文化与教育、个人品牌、内容型网站。

不太适合：信息密度极高的专业工具（交易、运维、设计软件）、游戏、面向儿童的产品。这些场景要的密度或情绪，和这套系统的留白与克制是相反的。
